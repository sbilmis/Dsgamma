## What was located

The author suggested checking the project's scripts folder. Its files and the Mathematica notebook were searched and the relevant implementations read:

- `scripts/mixing_angle_inputs.py` explicitly imports the nominal angles from the earlier dedicated study: 26.6 ± 0.6 degrees and 38.5 ± 0.1 degrees.
- `scripts/twopoint_ds1_matrix_sumrule.py` supplies the present residue calculation, at leading perturbative order plus local quark and mixed condensates (LO+d3+d5). It also defines `rotation_from_matrix` as a matrix-angle diagnostic.
- `scripts/twopoint_bs1_matrix_sumrule.py` explicitly states that its physical residues use the external published angle and that diagonalizing its truncated matrix is diagnostic only.
- `scripts/ds_angle_benchmark.py` distinguishes `previous_study_nominal` from `truncated_matrix_diagnostic`.
- `notebooks/Ds1_AA_AB_BB_two_point_sumrule.nb`, section 7, also treats the angle as an external input from the earlier study. It is generated by the present project's notebook builder.

The script and notebook inventories did not reveal a verified copy of the original 2025 mixing-angle implementation. Related filename searches of the parent Dsgamma project found the same external-angle usages and other radiative/multipole studies, not a verified original implementation.

## Limited baseline diagnostic, not a reproduction of the published study

To test whether the existing matrix code could serve as the original baseline, `ope_matrix` and `rotation_from_matrix` were evaluated with the earlier central inputs: mc = 1.27 GeV or mb = 4.18 GeV, ms = 0.126 GeV, qq = -0.0165 GeV³, ss/qq = 0.8, and m0² = 0.8 GeV². The code's current normalization was retained; the normalization issue was not reopened.

| Sector | Midpoint M², s0 (GeV²) | Local diagnostic at midpoint (degrees) | Local 3 x 3 grid range (degrees) | Published angle (degrees) |
| --- | --- | ---: | --- | --- |
| Ds | 4.5, 10 | 30.04964960 | 28.65947303-31.34224289 | 26.6 ± 0.6 |
| Bs | 11, 43 | 39.43370318 | 39.16255841-39.72679086 | 38.5 ± 0.1 |

The grid used the lower endpoint, midpoint and upper endpoint in each published mixing window: Ds M² = {3, 4.5, 6}, s0 = {9, 10, 11}; Bs M² = {9, 11, 13}, s0 = {42, 43, 44}. This is not an uncertainty propagation or a full continuous scan.

These numbers only show that the tested local diagnostic has **not reproduced the published baseline**. They do not establish that the published angles are incorrect. The equality of the OPE, scale treatment and numerical prescriptions between this diagnostic and the original study has not been established. Do not attribute this difference solely to an OPE term, normalization, or an input change without evidence. Do not quote these angles in the referee response.

To reproduce the diagnostic without running any script's output-writing main routine:

```python
import sys
sys.dont_write_bytecode = True
sys.path.insert(0, 'scripts')
from twopoint_ds1_matrix_sumrule import Inputs, ope_matrix, rotation_from_matrix

for sector, mh, m2_values, s0_values in [
    ('Ds', 1.27, (3., 4.5, 6.), (9., 10., 11.)),
    ('Bs', 4.18, (9., 11., 13.), (42., 43., 44.)),
]:
    inp = Inputs(mc=mh, ms=.126, qq=-.0165, kappa_s=.8, m0_sq=.8)
    for m2 in m2_values:
        for s0 in s0_values:
            matrix, _ = ope_matrix(m2, s0, inp)
            theta, _ = rotation_from_matrix(matrix)
            print(sector, m2, s0, theta)
```
